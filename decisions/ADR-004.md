# ADR-004: Hand-rolled jose session layer instead of Auth.js v5

**Date:** 2026-08-23
**Status:** ACCEPTED (Gate G1, 2026-08-23)
**Task Reference:** T-009
**Reversibility:** HIGH

## Context
spec-003-v1 named Auth.js v5 as the credentials/session library. During T-009 pre-implementation review, three of its acceptance criteria proved incompatible with next-auth's fixed flows: custom HTTP 429 + Retry-After rate-limit responses, strict adherence to the project error envelope on every API response, and headless JSON testability of the role matrix. ADR-003's security properties (httpOnly SameSite=Lax JWT, argon2id, tokenVersion revocation) do not depend on the library choice.

## Options Considered
1. **Auth.js v5 (next-auth@5.0.0-beta.32)** — batteries-included sessions; rejected: cannot emit 429/Retry-After from its credential flow, imposes its own response shapes conflicting with TDD §8, CSRF-form handshake complicates headless tests, and remains beta software.
2. **Hand-rolled sessions with `jose`** — ~120 lines owning cookie issuance, verification, revocation, and status codes directly; retains every ADR-003 property.

## Decision
Option 2. The requirements are few and precise; controlling them outright is simpler than fighting a framework's opinions. Recorded formally because it substitutes a stack-table entry (DCL-001).

## Consequences
+ Envelope/status-code compliance by construction; trivially testable; one less beta dependency.
− We own JWT/cookie correctness — mitigated by dedicated unit tests (sign/verify/expiry/tokenVersion) and endpoint integration tests; no OAuth provider support until needed.
− If SSO/OAuth arrives, migrating to Auth.js or adding providers means replacing this module (contained: callers depend only on `auth()`/`requireRole()`).
