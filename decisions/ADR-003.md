# ADR-003: Stateless JWT cookie sessions with argon2id password hashing

**Date:** 2026-08-23
**Status:** ACCEPTED
**Task Reference:** T-003
**Reversibility:** HIGH

## Context
v1 requires role-based auth (human decision T-002) with no OAuth/SSO requirement visible in the source workflow. User count is small (internal company staff + analysts).

## Options Considered
1. **JWT in httpOnly cookie (Auth.js v5 credentials)** — stateless verification per request; revocation via `tokenVersion` bump on password change/suspicion.
2. **Database-backed sessions** — instant server-side revocation; adds a session table and a DB round-trip per request.

## Decision
Option 1. Scale does not justify session-table management; revocation requirements are met by `tokenVersion` invalidation. Passwords hashed with argon2id via prebuilt-binary `@node-rs/argon2`.

## Consequences
+ No session storage; middleware verifies tokens cheaply; horizontal scaling unaffected.
− Immediate "kill all sessions" for a user = incrementing their `tokenVersion` (implemented, but slightly less direct than deleting a session row).
− If SSO/OAuth is requested later, Auth.js supports adding providers without discarding the session layer.
