# ADR-001: Single full-stack Next.js application instead of separate API + SPA

**Date:** 2026-08-23
**Status:** ACCEPTED
**Task Reference:** T-003
**Reversibility:** LOW

## Context
The platform needs a production-grade backend and an analytics dashboard for a small internal team (Trends staff + analysts). Human stakeholder selected "Next.js + PostgreSQL (Prisma)" over a separate API + SPA during decision capture (T-002). Team size is small; initial data volumes are modest (~hundreds of financial records per project).

## Options Considered
1. **Single Next.js 15 full-stack app** — REST route handlers under `/api/v1` plus React dashboard in one deployable.
2. **Separate NestJS API + React/Vite SPA** — stronger service boundary, independent scaling/deploys.
3. **Python (Django/FastAPI) backend + SPA** — different language ecosystem for the team.

## Decision
Option 1, per human selection and team-size fit. Domain logic lives in `src/server/services/*` behind the REST layer so that extraction into a standalone service remains possible without rewriting business rules.

## Consequences
+ One codebase, one deploy, shared TypeScript types and zod schemas between API and UI.
− Backend cannot scale independently of frontend (irrelevant at current scale).
− Route handlers are a thinner framework than NestJS (no built-in DI); discipline enforced via services layer instead.
